#+TITLE: org-bitwarden

Pull Bitwarden secrets into Org Babel blocks at evaluation and tangle time.

A literate config that needs an API token or password has two poor options:
write the secret into the Org file, or leave a gap to fill by hand after
every tangle.  org-bitwarden adds a =bw= block to the Library of Babel, so
=<<bw(item="...", field="...")>>= in a noweb block expands to the value
stored in Bitwarden.  The Org file holds only the item reference.

Secrets are read through [[https://github.com/doy/rbw][rbw]] (the default;
any field, including custom ones) or the official =bw= CLI (=password=,
=username=, =uri=, =notes= and =name= only).  Nothing is cached or stored by
the package.  A missing tool or a failed lookup is an error rather than an
empty expansion, and so is an empty value unless
=org-bitwarden-allow-empty= is set.  A tangled file that includes a secret
contains it in plain text.

* Install

Requires Emacs 27.1, and =rbw= or =bw= on =PATH=.

#+begin_src elisp
(package-vc-install "https://github.com/11xx/org-bitwarden") ; Emacs 29+
(require 'org-bitwarden)
#+end_src

With Elpaca, =(elpaca (org-bitwarden :host github :repo "11xx/org-bitwarden"))=;
with straight.el, =(straight-use-package '(org-bitwarden :host github :repo "11xx/org-bitwarden"))=.

* Use

#+begin_src org
,#+begin_src sh :noweb yes :tangle ~/.config/myapp/env.sh
export API_TOKEN='<<bw(item="00000000-0000-4000-8000-000000000000", field="api-token")>>'
export DB_PASSWORD='<<bw(item="database")>>'
,#+end_src
#+end_src

=item= is an item id or name; =field= defaults to =password=.  The same
lookup from Lisp is =(org-bitwarden-get ITEM FIELD)=.

To use =bw= instead of =rbw=, set =org-bitwarden-backend= to ='bw= and start
Emacs with =BW_SESSION= exported from =bw unlock --raw=.
=org-bitwarden-register-backend= adds a backend of your own.  The Commentary
in =org-bitwarden.el= covers noweb calls inside quoted strings and the
evaluation prompt.
